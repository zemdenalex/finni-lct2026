# Функциональная и компонентная архитектура

> §5 п.3 ТЗ. Также §3.4 п.1: «логика игровой экономики, учебный контент, хранение данных
> и пользовательский интерфейс разделены на понятные компоненты». Оценивается по §8.2.

## 1. Функциональная схема: игровая неделя

```
 первый запуск ─► онбординг S0: ник → облик Финни → имя → первые карманные → цель
                        │
                        ▼
  ┌──────────── начало недели ─────────────┐
  │ +400 стипендия · запас ⚡ · событие      │
  │ план: НУЖНО / ХОЧУ / ЦЕЛЬ               │  ← без плана действия недоступны (ТЗ 2.5.5.1)
  └──────────────────┬──────────────────────┘
                     ▼
  ┌──────────── неделя идёт ───────────────┐
  │ смены на работе (мини-игры) → 💰        │
  │ досуг → 😊 · покупки · копилка          │  ← каждое действие тратит ⚡
  │ события недели: выбор → последствие     │
  └──────────────────┬──────────────────────┘
          ⚡ не хватает ни на что  или  «Спать»
                     ▼
  ┌──────────── итоги недели ──────────────┐
  │ счета: корм → еда → жильё (+ событие)   │
  │ при нехватке: простая еда → копилка     │
  │   (с согласия) → «семья помогает»       │
  │ 😊 недели · очки роста · стадия         │
  │ план против факта, причина настроения   │
  └──────────────────┬──────────────────────┘
                     └──► следующая неделя
```

Фазы недели — перечисление `WeekPhase` в `app/finlit/lib/domain/world/contract.dart`:
`onboarding → weekStart → planning → living → review`. Какие действия доступны в какой фазе,
решает `World.canDo`. Отказ — не исключение, а `BlockReason` с кодом, фразой для ребёнка и
следующим шагом (ТЗ 2.5.9.3–4).

## 2. Слои

```
  content/*.json            числа экономики, работы, события — данные, не код
        │ читает
  lib/data/                 загрузка и проверка контента, хранение на устройстве
        │ отдаёт WorldConfig
  lib/domain/world/         правила мира на чистом Dart: WorldGame, журнал, свёртка
        │ контракт World
  lib/features/             экраны Flutter: только показывают и вызывают действия
```

🔴 **Правило зависимостей проверяется тестом.** В `lib/domain/` нет `import 'package:flutter/…'`
и `dart:io`: это проверяет `test/domain/layering_test.dart`. Поэтому весь домен тестируется без
эмулятора, за секунды.

## 3. Компоненты

| Компонент | Файл | Что делает |
|---|---|---|
| Контракт мира | `lib/domain/world/contract.dart` | `World` — все действия (`startWeek`, `plan`, `completeJob`, `buy`, `leisure`, `sleep`, `payBills`, `resolveEvent`, …), снимок `ResourceSnapshot`, итог `WorldResult` с причиной, карточка смены `JobOffer`, каталог, событие недели, онбординг |
| Мир | `lib/domain/world/world_game.dart` | Реализация `World` на журнале: правила недели, работы, покупок, досуга, сна, счетов, очков роста |
| Журнал | `lib/domain/world/world_entry.dart` | Запись журнала: вид, код причины, изменения конвертов, ⚡, 😊 |
| Свёртка | `lib/domain/world/world_fold.dart` | `WorldState.fold` — всё состояние из журнала: деньги, ⚡, 😊, фаза, владение, опыт, очки роста, стадия |
| Счета недели | `lib/domain/world/week_bills.dart` | Чистая функция: счета конца недели по правилу нехватки |
| События | `lib/domain/world/world_events.dart` | Модель событий из `events.json`: условия, варианты, эффекты |
| Каталог | `lib/domain/world/world_catalog.dart` | Товары, питомцы, цели и превью эффекта до покупки |
| Настроение | `lib/domain/world/world_mood.dart` | Причина настроения одной фразой (ТЗ 2.5.10.3) |
| Конфиг | `lib/domain/world/world_config.dart` | Все числа мира одним объектом. В игре он собирается из `economy.json`; значения по умолчанию нужны только тестам |
| Онбординг | `lib/domain/world/onboarding_keeper.dart` | Шаги первого запуска, продолжение после перезапуска |
| Тестовый мир | `lib/domain/world/fake_world.dart` | Вторая реализация контракта для тестов: экраны проверяются на ней и на настоящем `WorldGame` |
| Загрузка контента | `lib/data/world_content.dart`, `lib/data/world_config_from_content.dart`, `lib/data/world_game_loader.dart` | JSON → проверка схемы (ошибка называет поле) → `WorldConfig` → `WorldGame` (`openWorldGame`) |
| Хранение | `lib/data/storage.dart`, `lib/data/storage_io.dart`, `lib/data/storage_web.dart`, `lib/data/onboarding_store.dart` | `Storage`: на телефоне — JSON-файлы в приватном каталоге приложения (`FileStorage`); в браузерной сборке для команды — `localStorage` (`WebStorage`). Реализацию выбирает условный экспорт при сборке; прогресс онбординга |
| Экраны | `lib/features/world/…` | S0 онбординг, S1 комната, S2 город, S4–S5 магазины, S6 доска работ, S7 мини-игры, S8 досуг, S9 копилка, S10 событие, S11 итоги, S14 взрослым, S16 демо |

Запуск: `lib/main.dart` открывает сохранённый мир (`openSavedWorld` → `WorldGame`) и ведёт в
онбординг S0 или в комнату S1.

## 4. Журнал вместо чисел

**Баланс, энергия, счастье и прогресс нигде не хранятся числами.** Хранится журнал
append-only, у каждой записи есть причина (`reasonCode`). Текущие значения получаются
свёрткой журнала (`WorldState.fold`).

| Требование ТЗ | Как его закрывает журнал |
|---|---|
| 2.5.4.3 «баланс не меняется без объяснения» | Другого способа изменить число в коде нет |
| 2.5.9.1–2 «видно, что изменилось и почему» | `WorldResult` несёт изменения 💰 / ЦЕЛИ / ⚡ / 😊, причину и следующий шаг |
| 2.5.11 история и итоги | Фильтр журнала по неделе |
| 2.5.13.1 восстановление после перезапуска | `WorldGame.fromJson` восстанавливает мир из сохранённого журнала; неизвестные записи пропускаются, а не роняют приложение |

## 5. Контент отдельно от кода

- `content/economy.json` — все числа: стипендия, еда, жильё, питомцы, транспорт, одежда,
  декор, досуг, оплата и ⚡ смен, рост оплаты, правило нехватки, очки роста и стадии.
- `content/jobs.json` — содержание мини-игр (товары, покупки для сдачи, заказы, задачи
  программиста). Оплаты там нет, она только в `economy.json`.
- `content/events.json` — события недели: ситуация, варианты, эффекты, реплики Финни.

Копия лежит в `app/finlit/assets/content/world/` и едет в сборку. Совпадение копии с
`content/` проверяет `test/world_content_test.dart`. Схему проверяет загрузчик: битый файл
падает с именем поля (`test/world_config_from_content_test.dart`).

Новое событие добавляется одной записью в `events.json`, код не меняется (ТЗ 2.5.14).

⚠ Не всё ещё вынесено: часть содержания мини-игр и чисел эффектов пока лежит константами в
коде экранов. Статус — в
[05-matrica-trebovaniy.md](05-matrica-trebovaniy.md), строки 2.5.14 и 3.2.3.

## 6. Состояние на экранах и навигация

`ChangeNotifier` + `provider`: `WorldState` держит `World` и перерисовывает экраны после
действий. Навигация — именованные маршруты на стандартном `Navigator`.

Раскладка экранов: основная — альбомная (сцена слева, панель действий справа), портрет от
360 dp тоже поддерживается, у каждого экрана своя раскладка столбиком. Выбор делается по
соотношению сторон окна (`WorldLayout.isLandscape`).

## 7. Демонстрационный режим

Демо-панель и автопилот (`lib/domain/world/world_autopilot.dart`) проигрывают недели **теми
же действиями**, что ребёнок на экранах, поэтому стадия и деньги получаются из журнала, а не
из отдельной ветки логики. Отдельного профиля для проверки нет: автопилот играет в то же
сохранение, а «Начать игру заново» стирает его после подтверждения. Кнопки панели «Проверка» (`lib/features/world/demo/world_demo_screen.dart`): «Сыграть 1 неделю», «Сыграть 5 недель»,
«Дойти до 3-й стадии», «Полная ⚡», «Закончить неделю», «Открыть все профессии» (запись `demo.unlockAllJobs` в журнале: программист, курьер и выгульщик без покупок, стирается сбросом), «Показать событие» (список всех событий, запись `demo.showEvent`: выбранное становится событием недели и открывается S10), переход на любой экран
(«Экраны»), чек-лист «Приложение А: N из 12» и «Начать игру заново».
